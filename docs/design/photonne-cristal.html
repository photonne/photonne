Guía de diseño · SPA y Native

Photonne Cristal

La SPA era una aplicación web clásica: una barra superior con borde, un menú lateral pegado a la página y fotos encajadas entre ambos. La Native ya hablaba otro idioma: las fotos ocupan toda la pantalla y el cromo flota encima en cápsulas de cristal. Cristal es ese idioma, escrito para los dos clientes: la Native lo estrenó y la SPA lo adopta, con lo que la web hace mejor (teclado y ventanas anchas). Esta página es la referencia de ambos: tokens, componentes y reglas.

Tokens: la base de todo lo demás

En la SPA todo sale de src/app.css y src/lib/styles/ui.css; en la Native, de ui/theme/ y ChromeTokens.kt. Un componente nuevo usa estos tokens, nunca valores sueltos.

Es el mismo modelo que ChromeElevation (2 / 4 / 6dp) y sustituye al --shadow-raised único que hoy comparten 17 componentes.

:root {
  /* Forma: todo control es una píldora; los campos, un rectángulo de 14px */
  --radius-xs: 6px;  --radius-sm: 8px;  --radius-md: 14px;
  --radius-lg: 22px; --radius-xl: 28px; --radius-pill: 999px;
  --radius-control: var(--radius-pill); --radius-field: var(--radius-md);
  --control-h-sm: 32px; --control-h: 40px; --control-h-lg: 48px;

  /* Cristal (ChromePill): gris base, oscuro #26262b; ver .glass */
  --chrome-base: #e9e9ee;
  --glass-edge: rgb(255 255 255 / 0.6);    /* oscuro: rgb(255 255 255 / .1) */
  /* Tinte por componente: 70 % por defecto; 90 % la isla y 84 % las
     cápsulas de arriba, que casi siempre están sobre la página lisa */
  --glass-tint: 70%;
  --color-active-pill: rgb(0 0 0 / 0.07);  /* oscuro: rgb(255 255 255 / .12) */

  /* Elevación por rol (ChromeElevation 2 / 4 / 6dp) */
  --shadow-pill: 0 2px 8px rgb(15 23 42 / .12);
  --shadow-bar:  0 4px 16px rgb(15 23 42 / .12);
  --shadow-nav:  0 6px 24px rgb(15 23 42 / .16), 0 1px 3px rgb(15 23 42 / .10);

  /* Movimiento (MotionDurations) */
  --duration-chrome: 280ms; --duration-overlay: 320ms; --duration-emphasis: 220ms;
  --ease-standard: cubic-bezier(0.2, 0, 0, 1);
  --ease-spring: linear(0, .06 3%, .23 7%, .6 15%, .84 23%, .96 32%,
                        1.01 42%, 1.02 52%, 1.005 70%, 1);

  /* Geometría flotante */
  --float-margin: 12px; --chrome-h: 48px; --nav-pill-h: 64px;

  /* Color */
  --color-primary-fill: #c8960a;   /* oscuro: #ffd166; texto #1a1a2e */
  --color-favorite: #ff5252;
}

/* El desenfoque va en una capa detrás del contenido: un backdrop-filter en el
   propio elemento lo haría bloque contenedor de sus menús fijos. */
:where(.glass) { position: relative; }
.glass { isolation: isolate; border: 1px solid var(--glass-edge); }
.glass::before {
  content: ""; position: absolute; inset: 0; z-index: -1; border-radius: inherit;
  background: color-mix(in srgb, var(--chrome-base) var(--glass-tint, 70%), transparent);
  backdrop-filter: blur(30px) saturate(1.6);
}
@supports not (backdrop-filter: blur(1px)) { .glass::before { background: color-mix(in srgb, var(--chrome-base) 92%, transparent); } }
@media (prefers-reduced-transparency: reduce), (prefers-contrast: more) {
  .glass::before { background: var(--chrome-base); backdrop-filter: none; }
}
  • Neutros de la Native. Fondo claro #F8F9FA, texto #1E1E2E y secundario pizarra #64748B. En oscuro, #0A0A0C / #121214 / #1C1C20: es más negro, así que las fotos destacan más y el cristal se lee mejor.
  • Dos oros. --color-accent (#8A6400 en claro) es para texto e iconos activos porque cumple AA. El oro de marca #C8960A / #FFD166 rellena el botón principal (con texto oscuro, 6,6:1), el check de selección y el avatar.
  • Altura de control 40px, más cerca de los 48dp táctiles de la Native, y --control-h-lg 48px.

El shell: las fotos llegan hasta el borde

Es el cambio más visible y el que más hace parecer las dos apps hermanas (la maqueta de arriba). La página arranca bajo un hueco de --float-margin × 2 + --chrome-h (72px) y se desplaza por debajo de las cápsulas.

La isla de navegación

  • El sidebar se convierte en un panel de cristal separado 12px de los bordes, con radio 28px y --shadow-nav.
  • Los items son píldoras de 36px. El activo lleva el overlay neutro --color-active-pill y el icono relleno en oro, como FloatingNavBarItem.
  • El logo pasa del topbar a la cabecera de la isla, que al fin y al cabo es el sitio de la marca.
  • Al arrastrar fotos sobre un fijado, la píldora se ilumina en oro y escala a 1.03 con muelle.

Rail y cápsulas superiores

  • Rail (por debajo de 1100px, o cuando el usuario la pliega): la isla se estrecha a una cápsula vertical de 64px con iconos en círculos de 44px y el nombre en el title.
  • Búsqueda: cápsula de 48px que se ensancha al enfocarla (de 420 a 620px con muelle). Lleva el atajo Ctrl K de la paleta de comandos.
  • Herramientas: otra cápsula a la derecha con fecha, filtros, campana y avatar, como el HeaderChromePill del timeline.
  • Un sticky dentro de la página se pega bajo el cromo sin tocar nada: en Chrome su top se mide desde el borde interior del padding del contenedor.

En móvil, la misma app que la Native

La misma estructura que la Native: tres pestañas en una cápsula inferior, cromo que se esconde al hacer scroll y una barra de acciones que ocupa el sitio de la navegación al seleccionar. Puedes probarlo en la maqueta.

Qué cambia

  • Cápsula inferior de 64px, tan ancha como su contenido, separada 12px de los lados y 8px del borde más env(safe-area-inset-bottom). Las tres pestañas tienen el mismo ancho, como EqualWidthRow.
  • Pestañas: Fotos, Colecciones (recuerdos, personas, álbumes, carpetas, mapa…) y Más (subir, organizar, enlaces, utilidades, ajustes y admin), con el contador de notificaciones.
  • Se esconde al bajar con un umbral de 10px y vuelve al subir, al llegar arriba o 600ms después de parar, como ImmersiveChromeEffect. En una rejilla con scroll propio, el hueco reservado arriba y abajo pasa a las fotos y el cromo vuelve flotando sobre ellas, con solo las herramientas arriba (chrome.immersive, chrome.reclaimed).
  • Selección: arriba, una cápsula a lo ancho con cerrar, «12 seleccionadas» y seleccionar todo. Abajo, compartir, álbum, descargar y más en la misma cápsula de la navegación.
  • El degradado de la barra de estado mantiene legible el reloj sobre las fotos.

Selección

  • La barra opaca se divide en dos: la cápsula superior (cerrar, recuento, seleccionar todo) ocupa el sitio de búsqueda y herramientas, y la cápsula de acciones flota abajo en el centro.
  • Al papelera o archivar no hay diálogo: se aplica y aparece un toast con Deshacer, como en la Native.
  • Entran con translateY y muelle (280ms) y cruzan su opacidad con el cromo normal.

Rejilla y timeline

  • El hueco baja de 4 a 2px (SPACING en PhotoGrid) y las esquinas siguen rectas: la rejilla se lee como un mosaico continuo.
  • Una miniatura seleccionada se encoge (escala 0,88, radio 14px) con muelle sobre oro al 18%, con el check del oro de marca.
  • Píldora de fecha flotante arriba en el centro mientras se desplaza la vista; desaparece 1,5s después de parar.
  • Scrubber: el thumb de 4×32px pasa a un asa de cristal de 28×52px con chevrons, más una burbuja con la fecha en oro y marcas de año en píldoras, que solo se ven mientras se arrastra.
  • Píldora «Volver arriba» cuando estás a más de dos pantallas del principio; no aparece mientras hay selección, porque abajo están las acciones.

  • Dos cápsulas arriba con un hueco entre ellas por donde se ve la foto: a la izquierda cerrar, la fecha y el archivo (la Native muestra el lugar); a la derecha las herramientas y «más». El cristal es siempre el gris oscuro #242428, también en tema claro (.dark-surface / ViewerChromeColor).
  • Base de acciones abajo en el centro: favorito (corazón rojo --color-favorite cuando está activo), compartir e información. En un vídeo se quedan arriba, para no tapar sus controles. El resto va al menú «más».
  • Tira de miniaturas con lupa (AssetThumbnailStrip): solo en la Native por ahora. En la SPA el visor solo conoce la foto anterior y la siguiente.
  • Las flechas anterior y siguiente son círculos de cristal de 48px, discretos hasta que el puntero entra en la foto.
  • El panel de info es una isla de cristal con radio 28px separada 12px del borde, en lugar de un panel pegado. En móvil es una hoja inferior con radio 28px y un asa.
  • Fondo gris translúcido (rgb(66 67 74 / .8) con blur(28px), bastante más claro que el panel y las cápsulas) en lugar de negro: detrás se intuye la rejilla borrosa y el panel de info y las cápsulas se distinguen del fondo. El pase de diapositivas y los vídeos siguen en negro. Con prefers-reduced-transparency o más contraste, el gris es opaco.
  • El panel de información flota sobre la foto: la foto ocupa todo el ancho y sigue por debajo del panel, sin una franja de fondo entre las dos; la flecha «siguiente» se aparta del panel. En móvil el panel es una hoja inferior sobre la foto.
  • Por encima de todo: el visor se dibuja al final de <body> (portal.ts), fuera del apilamiento de la página que lo abre; abierto desde el panel del mapa, el cromo no tapa su botón de cerrar.
  • Al abrirse, el fondo aparece en 320ms y la foto crece hasta su sitio; el cromo llega 80ms después.

Páginas a pantalla completa, con sus herramientas en el cromo

Las páginas de fotos ya no guardan un margen fijo arriba para el cromo: la cabecera sube con el scroll y las fotos pasan por debajo del buscador, las notificaciones y las herramientas de la página. Lo que hace falta a mano se queda flotando arriba.

El cromo de cada página

  • <PageChrome bleed wide actions={…}>: con bleed la página ocupa toda la ventana (chrome.bleed); con wide, también por debajo de la isla de navegación (chrome.wide, solo el mapa). Sus paneles con scroll propio guardan el hueco dentro, como relleno: --bleed-top (la altura del cromo), --bleed-left (la isla, con wide) y, en móvil, --bleed-bottom (la barra inferior).
  • La isla de navegación mide lo que sus elementos, no todo el alto de la ventana; si la lista no cabe, se desplaza por dentro.
  • Las acciones de la página flotan. Los botones que cada página tenía junto a su título (PageHeader con actions) van a una cápsula del cromo, entre el buscador y las herramientas, y siguen a mano al hacer scroll: compartir y fijar un álbum, nueva subcarpeta, restaurar o vaciar la papelera, desarchivar todo, reconocimiento facial, nuevo álbum, mover a la papelera en archivos grandes… En escritorio son píldoras con icono y texto (una primaria o de peligro conserva su color); en móvil, solo el icono, con el texto como nombre accesible. PageHeader float={false} las deja en su sitio cuando la cabecera es parte de otra página (el panel del mapa).
  • Las filas de filtros no flotan (pestañas, tipos, orden de un índice, búsqueda dentro de la lista): suben con la cabecera. Un campo de búsqueda es un filtro, no una acción: en los índices de álbumes y carpetas está en esa fila.
  • La cabecera es parte del scroll. PhotoGrid recibe la cabecera de la página como lead y la dibuja encima de las fotos, fuera de la columna del scrubber (la línea temporal nunca tapa la portada de un álbum). La píldora de fecha solo aparece cuando las fotos llegan arriba.
  • Los menús del cromo (ChromeMenu) son popovers de cristal (capa superior, se cierran al pulsar fuera o con Esc) alineados bajo su botón; en móvil son hojas inferiores con asa.

Filtros y opciones de visualización

  • Filtros (embudo, en Fotos): ir a una fecha (G), fechas (todas, un día o un rango), agrupar por y orden (más recientes o más antiguas). El botón lleva un punto cuando algo no está en su valor por defecto. Se aplican en el cliente sobre el esqueleto de meses.
  • Opciones de visualización (ajustes), en toda página de fotos. Primero las opciones propias de la página, en bloques ViewOptionsGroup: el orden de un álbum (del álbum, más recientes, más antiguas) o las subcarpetas de una carpeta (Tarjetas o Lista y su tamaño). Después, las de todas:
    • Distribución: Mosaico (columnas, cada foto con su forma) o Cuadrícula (filas alineadas).
    • Proporción, solo con Cuadrícula: 1:1 (cuadrados iguales, cada foto recortada; por defecto) u Original (filas justificadas con la forma de cada foto).
    • Tamaño: un deslizador con cinco paradas marcadas (XS–XL) que también recorren +, − y Ctrl + rueda. Sin fotos a la vista (plegadas), no aparece.
  • Una sola preferencia para toda la app. La distribución y la proporción se eligen en el menú de cualquier página o en Ajustes › Apariencia: es el mismo valor, se guarda en el navegador como el tema (photonne.grid.layout, photonne.grid.ratio) y cambia todas las páginas a la vez. La vista por años de Fotos siempre va en filas.
  • Las vistas de álbumes y carpetas se llaman Tarjetas y Lista, para no confundirlas con la Cuadrícula de las fotos.

Páginas con paneles propios

  • Colecciones (CollectionView): chrome="page" por defecto; "inline" bajo las barras de su página (búsqueda, papelera compartida de administración), y "none" dentro de otra página (el panel del mapa), con las opciones y sus botones en su propia cabecera.
  • Mapa: ocupa toda la ventana, también por debajo de la isla de navegación. Sus capas quedan contenidas en la página (isolation: isolate), así que el cromo y la isla siempre van por delante. El título flota arriba a la izquierda, «Ver todas» va en el cromo y el panel de un grupo es una isla flotante a la derecha (una hoja sobre la barra inferior en móvil). «Ver todas» y el primer encuadre cuentan con lo que tapa el cromo; al cambiar de tamaño, el mapa mantiene el centro exacto de la URL.
  • Carpetas: subcarpetas y fotos son dos secciones plegables en un solo scroll, sin scrolls propios; plegar una deja todo el espacio a la otra. En el cromo: Nueva subcarpeta, Fijar, Más (con «Compartir con personas») y Opciones de visualización. En escritorio el árbol es una tarjeta que empieza bajo el cromo y se separa de la isla con el mismo margen que el resto de flotantes; el buscador flota limpio sobre las dos zonas. En móvil, el botón del árbol flota bajo el cromo y se va con él.

Lo que la web añade

Más allá de copiar la Native

Usan lo que el navegador ya trae, sin dependencias nuevas. Las marcadas como pendientes siguen siendo la dirección a seguir.

Morph de la miniatura al visor pendiente

Hoy el visor se abre con un fundido y la foto creciendo. Con la View Transitions API (onNavigate + document.startViewTransition en SvelteKit), la miniatura crece hasta convertirse en la foto del visor y vuelve a su sitio al cerrar. Es el equivalente del SharedTransitionLayout de la Native, con 320ms. Durante la transición el navegador no atiende clics, así que hay que cuidar los e2e.

Cristal que toma el color de la foto pendiente

En el visor, el tinte del cristal mezclaría un 10% del dominantColor de la foto; falta que el detalle del asset lo devuelva. Un atardecer da un cromo cálido y un paisaje nevado uno frío. Cuesta una variable CSS por foto.

Paleta de comandos

Ctrl/⌘+K abre desde cualquier página un cristal centrado para ir a cualquier sección, álbum o carpeta fijados, o buscar las palabras en las fotos (CommandPalette.svelte).

Movimiento con muelle en CSS

Un token --ease-spring con linear() da muelles reales sin JavaScript a las cápsulas, los menús, los diálogos y las tarjetas. Con prefers-reduced-motion, todo pasa a 0ms, como ahora.

Reglas

Accesibilidad y rendimiento

Contraste sobre el cristal

El texto sobre cristal puede perder contraste encima de una foto clara. El tinte al 60% más saturate lo evita en la mayoría de casos. Con prefers-reduced-transparency y prefers-contrast: more, el cristal pasa al fondo sólido al 92%. Los iconos del cromo mantienen 3:1 (WCAG 1.4.11).

Coste del desenfoque

backdrop-filter sobre una rejilla virtualizada que se desplaza puede costar fotogramas en equipos modestos. El desenfoque se limita al cromo (5–6 elementos a la vez) y nunca se aplica a las miniaturas. Conviene medirlo con el panel Performance en equipos modestos.

Teclado y foco

La isla y las cápsulas conservan el orden de foco y el enlace «Saltar al contenido». Un elemento que flota por CSS va en el DOM donde toca en el orden de foco (la base del visor va antes de las flechas). Las cápsulas que se esconden llevan inert.

Decisiones tomadas

  • Escritorio: la isla con etiquetas a partir de 1100px y el rail por debajo, salvo que el usuario elija otra cosa.
  • Móvil: tres pestañas como la Native (Fotos, Colecciones, Más), con las páginas /collections y /more en la SPA. No hay cajón lateral.
  • Toasts: arriba en todas las anchuras, como el snackbar de la Native.
  • Fotos y colecciones: la cabecera sube con el scroll; filtros y opciones de visualización en dos menús del cromo, en todas las páginas de fotos.
  • Fechas: el usuario filtra por un día o por un rango, y puede ordenar de más antiguas a más recientes.
  • Tamaño: cinco paradas, también con Ctrl + rueda.
  • Visor: gris translúcido sobre la rejilla borrosa, más claro que el panel y las cápsulas para que destaquen.
  • Acciones de página: flotan en el cromo en todas las páginas; las filas de filtros suben con la cabecera.
  • Cuadrícula: proporción 1:1 por defecto u Original; distribución y proporción, una preferencia global editable desde el menú de cada página o desde Ajustes › Apariencia.
  • Mapa: a todo el ancho, por debajo de la isla de navegación.
  • Carpetas: un solo scroll con secciones plegables; el árbol, una tarjeta separada de la isla.
  • Botones de hojas y diálogos: píldoras de 40 dp alineadas a la derecha, "Cancelar" o "Cerrar" con contorno y la acción rellena (oro, o rojo si no se puede deshacer). Las hojas de filtros, orden y menús no llevan pie. En la Native, las pantallas de formulario guardan con el botón principal a todo el ancho al final del contenido, nunca con texto en el cromo.
